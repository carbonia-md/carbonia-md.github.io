# Snippet Queue

Short-form drafts generated by `/sekai-snippet` from a `knowledge/` article, held
here until a human approves them. This is a workflow document, not an article: it
is never projected into the site.

## Lifecycle

`pending` -> **you edit it to** `approved` -> `npm run snippet:publish` -> `posted`

| Status | Meaning | Who sets it |
| ------ | ------- | ----------- |
| `pending` | Drafted, not reviewed. Never published. | `/sekai-snippet`, on append |
| `approved` | A human read it and cleared it to go out. | **you**, by hand, in this file |
| `posted` | Published; `url` holds the live post. | `npm run snippet:publish` |
| `rejected` | Not going out. Left in place as a record. | you, by hand |

**Approval is a manual edit to this file, and there is no other way to grant it.**
The runner reads `approved` entries and nothing else, so a draft nobody has
touched cannot be published. Read the draft against its source article before you
flip the status: the skill is required to ground every claim in that article, and
you are the check on whether it did.

Editing an approved draft's text? Update `chars` to match. The runner counts the
text itself and refuses the whole file when the two disagree, rather than quietly
correcting it.

## Entry format

One `## snippet-<id>` heading per entry, its fields as a list, and the post text
in a fenced block. `chars` counts Unicode code points; `url` stays empty until the
entry is posted.

````markdown
## snippet-2026-01-31-example

- slug: Category/article-slug
- created: 2026-01-31
- chars: 118
- status: pending
- url:

```text
The post text, exactly as it will be published. Grounded in the article named
by `slug` and carrying no claim that article does not make.
```
````

The publish runner and the adapter interface are documented in
[`scripts/tools/snippet/README.md`](../scripts/tools/snippet/README.md).
